# Stage 07 — Retrieval-augmented generation

**Budget:** 75 hours · **Suggested calendar:** weeks 46–50 at 15 hours/week · **Prerequisites:** Pass [Stage 06](06.md) and complete the earlier notebooks in this stage.

## What you will learn

- Parsing PDF/Markdown/HTML/DOCX/JSON/database records, provenance, OCR limits, and chunk strategies
- Embeddings, PostgreSQL/pgvector, lexical/BM25/dense/hybrid search, metadata filters, and reranking
- Recall/precision/MRR, answer support, citations, abstention, access isolation, and error attribution

## Study sequence and hours

1. **Learn and explain — 15 hours.** Read the notebook lessons and linked primary references. Produce a one-page explanation with one worked example for each topic above. Use CS50P/CS50 SQL and D2L alongside this course where listed in RESOURCES.md.
2. **Practice and debug — 22 hours.** Complete the notebooks below, then change inputs, add edge tests, and reproduce every important result from a fresh process. Keep a mistake log and repair at least one deliberately introduced bug per notebook.
3. **Build independently — 30 hours.** Implement the project brief from an empty folder under work/. Produce the deliverables below and compare with the reference only after a serious attempt.
4. **Assess and revisit — 8 hours.** Complete the closed-book gate, explain decisions aloud, and schedule 7/30-day reviews. If the gate fails, use the remediation path and retry with changed inputs.

## Mastery gate

Diagnose one failure each from parsing, chunking, embedding, ranking, reranking, and generation. Prove no cross-tenant evidence reaches the model.

Score correctness and reasoning (40), independent implementation (25), tests/debugging (20), and explanation/reproducibility (15). Pass at **80/100**, with no unhandled leakage, permission breach, invented evidence, or non-reproducible core result. A live-integration requirement cannot be passed by a mock or offline substitute. Record links to evidence in [progress.md](../../progress.md).

## If you get stuck

Return to exact keyword matching and source inspection if embedding results are mysterious; keep the same evaluation set when changing one retrieval component.

Explain what failed, show the smallest reproduction, and ask for a hint. Do not replace your entire solution with an answer file. Rebuild the corrected idea after 48 hours and include one unseen case.
