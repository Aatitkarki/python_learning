### Concepts in plain language

A relational table contains rows with named columns. A primary key uniquely identifies a row; a foreign key links to a valid row in another table. Normalization avoids storing the same fact in many places. For example, a record references a customer ID instead of copying the customer name into every transaction.

SQL SELECT chooses results, WHERE filters individual rows, GROUP BY forms groups, and HAVING filters aggregated groups. INNER JOIN keeps matching pairs. LEFT JOIN preserves every left-side row, using NULL when no right-side match exists. NULL means absent/unknown and is not automatically zero.

A transaction groups operations into one commit or rollback. An index is an additional data structure that can speed selected lookups but costs storage and write work. A query plan describes how the database intends to access and combine data.

### Worked example: follow the values

Customers A and B have sales 100 and 200 cents for A and none for B. An inner join omits B; a left join retains B. Summing with COALESCE produces A=300 and B=0. If a join duplicates each sale twice, the sum becomes 600: that is a cardinality bug, not a rounding issue.
