## Before the exercises: Demonstrating independent mastery

Read this in small pieces. Explain each new term in your own words, trace the example on paper, and change one input before continuing. If the arithmetic is unfamiliar, use [the math bridge](../MATH_START_HERE.md).

### Concepts in plain language

A reference solution demonstrates one implementation. Mastery means you can adapt the idea to a new request, explain its assumptions, test adverse cases, and recover from failure without copying the reference.

Start unfamiliar work by writing a contract: inputs, outputs, units, permission scope, missing-data behavior, and observable acceptance cases. Break the request into small functions, verify them, then connect boundaries. An architecture decision should state the choice, reason, and tradeoff.

Reproduction means another person can follow the documented setup and obtain the defined invariant results. Your current environment may hide dependencies, manual database state, or notebook variables. A restore drill tests that operational documentation is actually usable.

### Worked example: follow the values

For an unfamiliar revenue-growth endpoint, write cases for valid comparable years, missing prior year, zero denominator, mismatched company/currency/units, and unauthorized access. Calculate one expected result by hand before coding. During defense, trace how one case moves from the request to source lookup to arithmetic to response.

### Common mistakes to check

Automated tests cannot certify a timed closed-book attempt, another person’s reproduction, or an unrun deployment. Keep those evidence checks explicit.

**Ready to continue?** Explain the example without reading it, predict what a changed input will do, and identify one invalid or missing input. Then attempt the original notebook exercises. You do not need to finish a whole notebook in one session.
