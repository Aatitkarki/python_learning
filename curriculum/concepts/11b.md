## Before the exercises: Spark execution plans and partitions

### Concepts in plain language

Spark has a driver coordinating work and executors performing tasks. A DataFrame describes a distributed table with a schema. Many transformations are lazy: they build a plan without executing it. An action such as count or writing output triggers execution.

Partitions divide data into tasks. More partitions can increase parallelism but also overhead. A groupBy often requires an Exchange/shuffle. A physical plan shows chosen operations; inspect it rather than guessing from Python line order.

Hot-key salting adds temporary subkeys so one heavy group can aggregate in parts, then combines the partial totals. Parquet is column-oriented storage, useful when reading selected columns. A rolling ROWS window counts observed rows, not necessarily calendar days.

### Worked example: follow the values

If 92% of records have key 0, one final group dominates. Add a deterministic salt from 0 through 7, group by `(key,salt)`, then group partial sums by key. The final totals must match the unsalted result before you interpret any speed difference.
