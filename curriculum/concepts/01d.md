## Before the exercises: Modules, objects, tests, and algorithm cost

Read this in small pieces. Explain each new term in your own words, trace the example on paper, and change one input before continuing. If the arithmetic is unfamiliar, use [the math bridge](../MATH_START_HERE.md).

### Concepts in plain language

A module is a Python file you can import. A package groups modules. Separate parsing (read and validate), domain logic (calculate), and CLI (arguments and display) so one part can change without rewriting all the others.

A class describes objects with state and behavior. `self` refers to one instance. Composition means an analyzer contains or receives a repository object; inheritance means one class is a specialized kind of another. Prefer the relationship that matches the problem.

A unit test calls a small piece of behavior and compares observed and expected results. A mock replaces a boundary temporarily, such as making file opening fail. It should not replace the arithmetic you claim to test. Logging records useful events for diagnosis.

Big O describes how work grows with input size. Linear search checks up to n values; binary search repeatedly halves a sorted range, requiring about log2(n) steps. Recursion solves a smaller version of the same problem and needs a terminating base case.

### Worked example: follow the values

Searching a sorted list of 16 values by halving needs roughly four halvings, while a scan can inspect all 16. But sorting an unsorted list has a cost; include it when deciding whether one binary lookup is worthwhile. For recursive directory size, the base case is a file's size; a directory sums child sizes. Skip symbolic links or detect cycles.

### Common mistakes to check

Class-level mutable lists can accidentally share state across instances. Recursion without a shrinking problem/base case never completes.
