## Before the exercises: Authorization across caches and saved state

Read this in small pieces. Explain each new term in your own words, trace the example on paper, and change one input before continuing. If the arithmetic is unfamiliar, use [the math bridge](../MATH_START_HERE.md).

### Concepts in plain language

Authentication establishes identity; authorization decides which resource that identity may access. Test two independent credentials within a tenant and credentials from another tenant, reflecting the app's actual permission model.

A cache saves earlier results. If its key omits scope/version, another caller might receive the wrong result. Even with scoped keys, recheck access after permission changes. Revocation invalidates a previously valid credential or permission.

Citations, saved workflow state, exports, and backups can expose the same protected data through different paths. Cover them explicitly. A public resource is accessible under its declared policy, not because its text claims to be public.

### Worked example: follow the values

Warm a cache by fetching B's private document using B's key. A's subsequent request must fail. Revoke B's key; another B request must fail too, despite cached content. Include a public-document success case so you can distinguish selective authorization from a broken service.
