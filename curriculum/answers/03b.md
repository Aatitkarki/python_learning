## 03b-E1: Bound filter

**Question:** Return (id,amount) rows for a customer ordered by id, using SQL parameters.

**Answer:**

```python
def customer_orders(conn, customer):
    return conn.execute("SELECT id, amount FROM orders WHERE customer = ? ORDER BY id", (customer,)).fetchall()
```

**Checks:**

```python
assert customer_orders(conn, "A") == [(1, 10), (2, 20)]
assert customer_orders(conn, "' OR 1=1 --") == []
```

**Why it works:** Parameter binding treats the entire input as data, including quotes and SQL-like text.

## 03b-E2: Running totals

**Question:** Return (id,running_amount) per customer, ordered by id. Use SUM OVER with an explicit ROWS frame.

**Answer:**

```python
def running_totals(conn):
    return conn.execute("SELECT id, SUM(amount) OVER (PARTITION BY customer ORDER BY id ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) FROM orders ORDER BY id").fetchall()
```

**Checks:**

```python
assert running_totals(conn) == [(1, 10), (2, 30), (3, 7)]
```

**Why it works:** An explicit frame removes ambiguity about equal sort keys.

## 03b-E3: Atomic batch

**Question:** Insert rows inside a transaction; any duplicate key rolls back the entire batch.

**Answer:**

```python
def insert_batch(conn, rows):
    with conn:
        conn.executemany("INSERT INTO orders VALUES (?, ?, ?)", rows)
```

**Checks:**

```python
expect_error(sqlite3.IntegrityError, lambda: insert_batch(conn, [(4, "C", 4), (1, "D", 5)]))
assert conn.execute("SELECT COUNT(*) FROM orders").fetchone()[0] == 3
```

**Why it works:** Partial ingestion can create inconsistent reports; atomicity keeps the batch all-or-nothing.
