## 03a-E1: Column standardization

**Question:** Standardize each column using population std. Constant columns become zeros. Return a NumPy array.

**Answer:**

```python
def standardize(x):
    import numpy as np
    x = np.asarray(x, dtype=float)
    std = x.std(axis=0)
    return (x-x.mean(axis=0))/np.where(std == 0, 1, std)
```

**Checks:**

```python
z = standardize([[1, 7], [3, 7]])
assert np.allclose(z, [[-1, 0], [1, 0]])
```

**Why it works:** In ML, save training mean/std and reuse them on validation and test data.

## 03a-E2: Monthly spending

**Question:** Parse dates and amounts, group by calendar month string YYYY-MM, return a sorted Series. Use a copied frame.

**Answer:**

```python
def monthly_spending(frame):
    import pandas as pd
    frame = frame.copy()
    frame["date"] = pd.to_datetime(frame["date"], errors="raise")
    frame["amount"] = pd.to_numeric(frame["amount"], errors="raise")
    return frame.groupby(frame["date"].dt.strftime("%Y-%m"))["amount"].sum().sort_index()
```

**Checks:**

```python
frame = pd.DataFrame({"date": ["2026-02-01", "2026-01-01", "2026-01-03"], "amount": [4, 2, 3]})
assert monthly_spending(frame).to_dict() == {"2026-01": 5, "2026-02": 4}
```

**Why it works:** This float-based exploration is fine for visualization; exact ledger arithmetic should retain decimal or integer cents.

## 03a-E3: Safe join

**Question:** Left-join orders and customers on customer_id; enforce many-to-one and preserve row count.

**Answer:**

```python
def enrich(orders, customers):
    return orders.merge(customers, on="customer_id", how="left", validate="many_to_one")
```

**Checks:**

```python
orders = pd.DataFrame({"customer_id": [1, 1, 2], "amount": [1, 2, 3]})
customers = pd.DataFrame({"customer_id": [1, 2], "name": ["A", "B"]})
assert len(enrich(orders, customers)) == 3
expect_error(pd.errors.MergeError, lambda: enrich(orders, pd.concat([customers, customers])))
```

**Why it works:** Join explosions can silently distort totals and training distributions.

## 03a-T: Independent assignment

**Question:** Profile missing values, duplicates, date ranges, and outliers in expenses.csv. Write a cleaning report and a three-day rolling mean. Explain every exclusion.

**Test your own work:** [Interface, starter, and acceptance tests](../assignments/03a.md)

**Worked answer:** The answer writes clean.csv, quarantine.csv, rolling.csv, and report.json. Invalid dates, nonfinite/negative amounts, and blank categories receive explicit rejection reasons and source row numbers. Exact duplicates are quarantined under a stated fixture policy; genuine identical purchases need transaction IDs instead. IQR outliers are flagged rather than silently dropped. Daily aggregation is reindexed to a complete calendar before a trailing three-day mean: amounts 9 on Jan 1 and 3 on Jan 3 produce (9+0+3)/3=4 on Jan 3. This convention means zero recorded spending on missing days, not evidence of no activity. The bundled clean fixture should have no rejected records.
