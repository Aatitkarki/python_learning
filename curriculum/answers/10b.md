## 10b-E1: Required configuration

**Question:** Read a mapping with DATABASE_URL and API_KEY; reject missing/blank values or API_KEY shorter than 24 characters.

**Answer:**

```python
def validate_config(env):
    result = {k: env.get(k, "").strip() for k in ("DATABASE_URL", "API_KEY")}
    if not all(result.values()) or len(result["API_KEY"]) < 24: raise ValueError("Incomplete configuration")
    return result
```

**Checks:**

```python
assert validate_config({"DATABASE_URL": "postgresql://db/example", "API_KEY": "x"*32})["API_KEY"] == "x"*32
expect_error(ValueError, lambda: validate_config({}))
```

**Why it works:** The length check is only a local training guard, not a complete credential policy.

## 10b-E2: Release gate

**Question:** Return True only when tests, evals, migration_rehearsal, and restore_drill are all exactly True.

**Answer:**

```python
def release_ready(evidence):
    return all(evidence.get(k) is True for k in ("tests", "evals", "migration_rehearsal", "restore_drill"))
```

**Checks:**

```python
assert not release_ready({"tests": True, "evals": True})
assert release_ready(dict.fromkeys(["tests", "evals", "migration_rehearsal", "restore_drill"], True))
```

**Why it works:** A release checklist is useful only when each item points to an actual artifact.

## 10b-E3: Schema compatibility

**Question:** A service supports schema versions inclusive [minimum,maximum]. Return whether current is compatible; reject inverted bounds.

**Answer:**

```python
def compatible(current, minimum, maximum):
    if minimum > maximum: raise ValueError("Invalid range")
    return minimum <= current <= maximum
```

**Checks:**

```python
assert compatible(3, 2, 4)
assert not compatible(5, 2, 4)
```

**Why it works:** Expand-contract migrations can keep old and new application versions compatible during rollout.
